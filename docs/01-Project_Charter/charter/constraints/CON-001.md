# CON-001 — Operação offline e APIs externas opcionais

**ID:** CON-001  
**Status:** `refinement`  
**Version:** `v1`  
**Evidência:** `DOCUMENTED` no [README do projeto](../../../../README.md).

## Restrição

O sistema deve oferecer operação local sem dependência obrigatória de serviços externos para suas funções essenciais, podendo utilizar APIs externas de processamento quando configuradas e autorizadas pelo ambiente. A ausência dessas APIs não deve impedir as funcionalidades locais compatíveis com os recursos disponíveis. Quando utilizado, o motor local de inferência não deve ser exposto publicamente.

## Origem

Objetivos de segurança do README do produto e decisão posterior do responsável pelo projeto permitindo serviços de processamento externos opcionais, inclusive APIs de provedores como OpenAI.

## Motivo

Manter uma alternativa offline operacional e reduzir a superfície de exposição, sem bloquear benefícios opcionais do processamento remoto.

## Impacto

A solução deve preservar as funcionalidades essenciais offline que forem definidas no Scope; chamadas a APIs externas são opcionais e dependem de disponibilidade e autorização. O Scope deverá identificar os limites das funcionalidades offline e os dados que podem sair do ambiente local. Seleção de fornecedores, contratos e mecanismos técnicos pertencem às etapas posteriores.

## Forma de verificação

Confirmar que as funcionalidades essenciais definidas no Scope operam sem rede externa, que a indisponibilidade de APIs não bloqueia a alternativa local compatível e que a inferência local não possui exposição pública não autorizada.

## Condição de revisão

Mudanças na obrigação de suporte offline, no envio de dados a terceiros ou no isolamento local exigem decisão explícita sobre impactos e riscos.
